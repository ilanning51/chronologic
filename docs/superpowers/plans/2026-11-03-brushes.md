# Brushes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The tray's four tiles become toggleable brushes: New line draws a line by dragging on paper with a live time chip, Step and Sub-goal place a stop per tap on a line, Today draws the day by dragging on paper.

**Architecture:** The plane already turns pointer events into gestures through a pure `Recognizer`. A brush adds one new target, `brush`, which the plane hands the recognizer for a press on empty paper while a brush is on, exactly as it hands it `marquee` when Shift is held. The app keeps the brush as React state and routes `brush` taps and drags to the right drawing code, most of which already exists (tile drop, sun drag).

**Tech Stack:** React 18, TypeScript, Vitest + Testing Library, plain CSS.

**Spec:** `docs/superpowers/specs/2026-11-03-brushes-design.md`

## Global Constraints

- A line's time is its routed length: `pathLength(routeThrough([start, end]).vertices)` world units = seconds.
- One brush on at most; the brush is app state, never saved, off at start.
- Shift on paper is the marquee, brush or not.
- Every hit target stays at least 44 px (`--hit` / `--tap`).
- Each brush stroke or brush tap is one undo step (`store.begin()` / `store.end()`).
- No notifications, scores, counts (design/flow-conditions.md).

## Review Focus

1. A second finger mid-stroke must leave no line or day behind (Task 1 test `a second finger on a brush stroke ends it cancelled`; Task 4 test `a pinch begun mid-stroke draws nothing`).
2. Tapping a tile with a pointer must toggle once, not twice (the recognizer's tap plus a click) (Task 3 test `a pointer tap on a tile toggles once`).
3. A press on a stop with a brush on still drags the stop and draws nothing (Task 4 test `with a brush on, a drag that starts on a stop moves the stop`).
4. Escape in an open name field cancels only the name; the brush stays on (Task 4 test `Escape in a name field keeps the brush`).
5. Existing tests that tapped New line to get a line must now draw one; none may be deleted (Task 4 step 1).

### Task 4: The app draws with the brush

**Files:**
- Modify: `src/ui/App.tsx`
- Test: `src/ui/App.test.tsx`

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces: none outside App.

Behaviour, from the spec, in App:
- State `brush: Tile | null` (+ ref). A `tap` on a tile toggles it (`b === tile ? null : tile`); `onBrushKey` does the same. The plus closing the tray sets `brush` null. Escape (not `defaultPrevented`) sets it null alongside the selection.
- Remove `newLine()` and its camera fly; the line tile's tap is now a toggle.
- `tap` on `brush`: everything a paper tap does except closing the tray; then, for `circle`/`triangle`, place a stop at the tap: refactor `dropTile` into `placeStop(shape, at: Point)` (snap with `snapToAll` at `screenToWorld(at)`, `addStop` on the first hit, `join` on the rest, pin it, open naming) wrapped in `store.begin()`/`store.end()`; the tile-drag drop calls the same function.
- `dragStart` on `brush`: `line` → `lineDraw.current = { from: g.at }`; `sun` → `drawing.current = { from: g.at, ids: [] }` (the sun drag path does the rest); `circle`/`triangle` → nothing.
- `dragMove` while `lineDraw`: ghost = the routed points `routeThrough([fromWorld, atWorld]).vertices` mapped to screen, drawn with `DayGhost`; `setLegTime({ x: at.x, y: at.y, seconds: pathLength(...) })`.
- `dragEnd`: if `g.cancelled` and the target is `brush`, clear `lineDraw`/`drawing`, the ghosts and the chip, and make nothing. Otherwise a line drag dispatches `newTrack` with `origin` = world of `from`, `goal` = world of `at`, then `setNaming({ id: goalId, kind: 'goal', trackId: id })`; the camera does not move.
- `Plane` gets `brush={brush}`; `Tray` gets `brush` and `onBrushKey`.
